## What I'm building now

### DTC Revenue Operations Agent
A Claude-based internal AI agent for a synthetic portfolio of ecommerce brands.

The system separates deterministic business logic from model reasoning:

- Python/SQL detect account signals and rank which accounts deserve attention.
- Claude decides what additional context to retrieve through constrained tools.
- Recommendations must pass schema, source-reference and business-rule checks before publication.
- Confidence is derived from data quality, freshness and reconciliation — not generated by the model.
- Business-system actions remain behind human approval.

The evaluation suite covers growth opportunities, stale data, attribution conflicts, prompt injection and genuinely ambiguous business signals.

### Career Agent
A local-first AI job intelligence platform combining deterministic rules with LLM interpretation of unstructured job data.

It includes:

- multi-source ingestion and normalization
- deterministic eligibility and lifecycle rules
- evidence-backed recommendations
- LLM interpretation of unstructured job descriptions
- regression and release gates
- provider fallback and failure recovery
- local-first privacy

One principle carries through both projects: **AI does not replace deterministic logic when deterministic logic is the safer tool.**

## How I build AI systems

**Facts before reasoning**  
Metrics, reconciliation and business rules stay outside the LLM when they can be calculated deterministically.

**Tools over giant prompts**  
Agents retrieve the context they need instead of receiving entire systems or databases in context.

**Read-only first**  
I prefer constrained read tools and explicit approval before meaningful business-system side effects.

**Fail closed**  
Invalid schema, missing sources or blocked conditions should stop publication rather than produce a best guess.

**Evaluate before tuning**  
I preserve the first baseline, classify failures, and only then decide whether the problem is code, tool design, prompting, model behavior or legitimate ambiguity.

**Observe the system**  
Tool calls, rejected outputs, latency, tokens and cost are part of the engineering problem.
